# EventMesh — Architecture Decisions

Concise ADRs. Full design rationale is in [`ARCHITECTURE_V2.md`](ARCHITECTURE_V2.md).
Status: all **Accepted** and implemented unless noted.

## Platform & structure

**ADR-1 · Domain-driven modular monolith (not microservices).**
One FastAPI deploy partitioned by domain (`app/modules/{users,organizers,events,
providers,sync,search,notifications}`), each owning `router/service/repository/
schemas/models`. Cross-module calls go service→service. Rationale: MVP velocity +
low ops; clean seams allow later extraction. Hexagonal ports used only where
implementations genuinely vary (providers, search).

**ADR-2 · Stack.** FastAPI + Python 3.12, async SQLAlchemy 2, Alembic, Pydantic v2,
Supabase Postgres, Supabase Auth, Supabase Storage (deferred), Render (backend),
Vercel (frontend), Docker, GitHub Actions (CI + scheduler). All final.

## Data & persistence

**ADR-3 · Native / Imported / Visible separation.** `native_events` (hosted) and
`imported_events` (aggregated) are distinct tables. **Visible = a PostgreSQL VIEW**
(`visible_events`) unioning published/public native + canonical/active/future
imported — not a physical table (avoids dual-write consistency bugs). Imported
records are never exposed directly.

**ADR-4 · Migrations via Alembic, run at container start.** Render free tier has
no pre-deploy hook, so the Docker CMD runs `alembic upgrade head` before uvicorn
(idempotent). Every autogenerated migration's downgrade is hand-hardened to drop
enum types (autogenerate omits them).

**ADR-5 · Postgres-only, asyncpg, pgBouncer-safe.** SQLite banned (fail-fast
config check). `statement_cache_size=0` for the Supabase transaction/session
pooler. UUID PKs; `TimestampMixin.updated_at` uses a **Python-side `onupdate`**
(not SQL `func.now()`) so serializing a just-updated row doesn't trigger a lazy
async load (MissingGreenlet).

## Auth & authorization

**ADR-6 · Supabase Auth; FastAPI is a pure resource server.** Google + Email OTP,
no passwords. FastAPI only validates JWTs — **JWKS/ES256 first** (asymmetric),
HS256 shared-secret as fallback. JIT profile provisioning on first authed call.

**ADR-7 · Service-role + app-layer authorization for MVP.** FastAPI is the trusted
client; authz enforced in app (role guards, org membership). RLS is a documented
future hardening. Admin sync guarded by a separate `X-Admin-Token`.

## Aggregation engine

**ADR-8 · Provider framework hides transport.** `BaseProvider` template
(`fetch→normalize→validate→sync`, fail-soft per item); every provider returns a
`NormalizedEvent`. Registry populated at startup (key-gated for APIs). Official
API preferred (Eventbrite); responsible scraping otherwise (Meetup, Luma) with a
shared `ScrapeClient` (retry/backoff, rate limiting, realistic headers).

**ADR-9 · Deterministic dedup + canonical selection.** `dedup_hash` = normalized
title + hour-bucketed start + city. Canonical winner per group = **provider
priority → metadata completeness → stable `(provider, external_id)` tiebreak**.
Heuristic and observable (a review queue is future work); conservative to prefer
missed merges over false merges. Provenance preserved via `sources[]`.

**ADR-10 · Fail-soft synchronization.** GitHub Actions (every 6h) → `POST
/admin/sync`. One provider failing (or the merge step) never aborts the run or
corrupts data; per-provider health + a `SyncReport` are persisted to `sync_runs`.
Chosen over an in-process scheduler (Render sleeps; no long-lived process).

## Search

**ADR-11 · Search on the visible read model; Postgres FTS now, pgvector later,
no Meilisearch.** Browse/search query `visible_events` behind a repository so the
engine can evolve without touching callers. (Phase "Discovery Platform" builds
this out.)

## Deferred / documented-not-built

Image uploads (only `image_url`/`cover_image_url` kept), `event_media` multi-image
table, notifications delivery, payments, semantic search, waitlist auto-promotion,
imported-event retention job, git-history rewrite (pre-launch), RLS enforcement.
